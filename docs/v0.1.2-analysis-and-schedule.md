# FFFVedio v0.1.2 研判与排期：剪辑 + 字幕

> 状态：**已实现（v0.1.2，2026-11-08）**。本文记录的现状、根因、目标设计、排期与验收口径均已落地；提交前已完成 9.4 全量回归（Go build/vet/test 与前端 typecheck/build 全绿）。
>
> 范围按用户确认：方案 A（需求 3 / 8 / 9 / 7 MVP / 10）。
> 0.1.2 把字幕环节并入剪辑：新增 `BUILD_EDIT` / `CONFIRM_EDIT` 阶段，视频生成后自动生成剪辑计划与字幕时间轴；
> 剪辑页可预览视频、调整片段启停/入出点（续接模式允许时也可排序）与字幕时间轴。
> 旧「生成字幕」开关移除，新任务默认生成字幕；续接方式为 `last_frame` 时禁止排序，只允许裁剪/启停。
> 需求 10 只做「音色绑定视频生成提示词」，不接外部 TTS。

---

## 一、结论摘要

1. **当前字幕链路不是「没有做」，而是「做了但有几处会丢字/错位/叠字」**。最严重的三个问题都已定位到具体代码：
   - 长句换行只保留前两行，**第三行起直接丢弃**（`video_models.go:1445-1468`）。
   - 用户文本里的 `{}` 会被 ASS 当成控制标签，**整段文字消失**（`video_compose.go:1183-1200`），已实测 `{测试}ABC` 只渲染出 `ABC`。
   - 手工字幕没有重叠消解，越界字幕全部贴到片尾，**多条叠在一起**（`video_models.go:1283-1320`）。
2. **旧流程字幕默认关闭**，新建任务不勾选就完全不会生成（`video_models.go:162`、`frontend/src/types/video.ts:565`）。0.1.2 移除这个开关，新任务在 `BUILD_EDIT` 自动生成字幕；只有旧任务显式 `subtitles=false` 的保持关闭。
3. **默认字体「思源黑体」在 Windows 上通常不存在**。实测本机 libass 先回退到 ArialMT，再逐字回退到 MicrosoftYaHeiUI；换一台没装中文字体的机器就会出现方块/缺字。0.1.2 改为内置 `Noto Sans SC`，并用 ffmpeg `ass` 滤镜的 `fontsdir` 指向内置字体目录。
4. **剪辑能力目前只有自动预处理，没有用户可操作的剪辑计划**。`VideoComposePrep` 只记录自动选段/冻帧裁剪/拼接/归一的结果（`video_models.go:359-372`），没有 `order / enabled / inPoint / outPoint`。
5. **阶段设计改为新增 `BUILD_EDIT` / `CONFIRM_EDIT`**：`BUILD_EDIT` 负责生成默认剪辑计划、重建预览画布、自动铺字幕；`CONFIRM_EDIT` 是剪辑与字幕确认页。旧 `BUILD_SUBS` / `CONFIRM_SUBS` 在读取时映射到新阶段，旧 DB 不需要改表。`last_frame` 续接模式下禁止排序，只允许裁剪与启停。
6. 字体目录方案已实测可用：把一个**未安装**的测试字体放进独立目录，`ass` 滤镜带 `fontsdir` 时 libass 从该目录选中字体；不带时回退到 ArialMT。说明内置字体不依赖用户机器安装。
7. 总体量约 **14 人日纯开发**，含 20% 缓冲约 **17.5 人日**。单人开发约 3 周；两人并行（后端剪辑管线 + 前端时间轴）约 9–10 个工作日。

## 三、根因研判（需求 3 / 9）

### 3.1 字幕全部不显示

| # | 根因 | 位置 | 说明 |
| --- | --- | --- | --- |
| 1 | 旧流程字幕默认关闭 | `video_models.go:162`、`types/video.ts:565` | 0.1.1 新建任务不主动勾选就没有 SRT/ASS，也不烧录。0.1.2 移除开关，新任务默认生成；旧任务 `subtitles=false` 保留。 |
| 2 | 默认字体不存在 | `video_models.go:521-529`、`video_compose.go:1159-1180` | 默认 `思源黑体`；Windows 常见字体里没有该族名。实测日志：`fontselect: (思源黑体) -> ArialMT` → `Glyph 0x5B57 not found` → `MicrosoftYaHeiUI`。没有 CJK 回退字体时就是方块/空白。0.1.2 内置 `Noto Sans SC` 并传 `fontsdir`。 |
| 3 | `{}` 被当 ASS 标签 | `video_compose.go:1183-1200` | 对 `cue.Text` 只做了 `\n → \N`，没有转义 `{` / `}` / `\`。实测 `{测试}ABC` 只渲染 `ABC`。 |
| 4 | 烧录失败静默降级 | `video_compose.go:1265-1295` | 一次渲染失败后降级为无字幕成片，只在 Run.Warnings 留一句；UI 提示不够醒目。 |
| 5 | 字幕阶段被跳过 | `video_pipeline.go:1049-1055` | 旧逻辑 `Run.Subtitles == nil` 就直接进 COMPOSE；没有台词或关闭字幕时用户看不到任何解释。0.1.2 改为进入 `BUILD_EDIT`，即使旧任务关了字幕也能剪辑。 |

### 3.2 字幕部分丢失

| # | 根因 | 位置 | 说明 |
| --- | --- | --- | --- |
| 1 | 换行只保留两行 | `video_models.go:1463-1465` | `if len(lines) == 2 { break }`，后面的 `runes` 直接丢掉。100 字长句只留下约 36 字。 |
| 2 | 断句只认句末标点 | `video_models.go:1408-1413` | `。！？…；!?;` 和换行；逗号、顿号、空格都不切。长句必然超两行，随后被上一行规则截断。 |
| 3 | 过短碎片被合并 | `video_models.go:1432-1438` | `<4` 字的片段并回上一句，方向没问题，但会让单条更长，放大截断风险。 |
| 4 | 时间不够时静默丢条 | `video_models.go:1392`、`video_compose.go:965` | `display > cursor` 才追加；槽位被压到极短时整条消失，没有告警。 |
| 5 | 200 条硬上限 | `video_models.go:1285-1288` | 超出直接丢弃；长视频/密集对白会中招。 |
| 6 | 长镜头拆段后台词只在首段 | `video_models.go:1215-1221` | 这是生成侧的有意设计（台词只随首段下发），但 UI 没有解释，用户会以为后续段的字幕丢了。 |

### 3.3 字幕与语音不同步

| # | 根因 | 位置 | 说明 |
| --- | --- | --- | --- |
| 1 | `FillWindow` 把短句拉满整段 | `video_compose.go:758-759`、`video_models.go:1349-1351` | 片段自带音轨时 `FillWindow=true`，`spoken=window`，一句 5 字台词会被拉满 8 秒；声学对齐失败时就明显「字幕挂太久」。 |
| 2 | 声学检测只有下限 | `video_compose.go:770-777`、`1016-1028` | `-35dB / 0.2s`，只判断覆盖率 `<20%` 不可信；连续 BGM/噪声会让覆盖率接近 100%，说话时钟变成整条时间轴。 |
| 3 | 声学对齐失败原因不可见 | `video_pipeline.go:1282-1290` | 只写进 Warnings；编辑页只显示 `timingSource`，用户不知道这次是 `measured` 还是 `aligned`、为什么没对齐。 |
| 4 | 计划时间轴 vs 实测时间轴 | `video_compose.go:725-766` | 已经按片段实测时长修正，方向正确；但剪辑入/出点接入后必须继续以「实际入片文件」为准。 |
| 5 | 拼接顺序/裁剪与字幕轴不一致的风险 | `video_compose.go:1397-1522` | 当前选段顺序来自 `run.Renders`，字幕来自 `run.Plan`；两者目前同序，但加入剪辑计划后必须统一成同一份 `EditPlan`，否则重排后必错位。 |

### 3.4 断句 / 换行不对

- 自动字幕：只按句末标点切，长句不按逗号/顿号二次切；再叠加「两行截断」，表现为句子被吃尾。
- 手工字幕：`renderASS` 直接用 `cue.Text`，不做换行建议；`WrapStyle: 2` 表示不自动换行，长句会溢出画面。
- 逐条字号/位置：`\an` / `\fs` 覆盖是拼在文本前面的，用户文本里若已有 `{}`，两者会互相干扰（见 3.1）。
- 中英混排：`wrapSubtitleText` 只按固定字符数切，英文按 42 字符、中文按 18 字，不识别单词/标点边界，英文可能从单词中间断开。

### 3.5 手工编辑语义

- 目前「保存字幕修改」= 立即 `Confirmed=true`（`video_pipeline.go:709`），没有「草稿」概念；用户以为只是暂存，实际合成已按它烧录。
- 保存时只做夹取、排序、重编号（`video_models.go:1283-1320`），不消解重叠、不校验阅读速度/单行长度。
- 起始时间超过成片时，所有越界条目都被改成 `total - 0.4`（`video_models.go:1300-1303`），多条会叠在同一位置。

### 3.6 已做的实测验证

```text
# 字体
fontselect: (思源黑体, 400, 0) -> ArialMT, 0, ArialMT
Glyph 0x5B57 not found, selecting one more font for (思源黑体, 400, 0)
fontselect: (思源黑体, 400, 0) -> MicrosoftYaHeiUI, 1, MicrosoftYaHeiUI

# ASS 花括号吞字（720x1280，80px）
"ABCD"        -> crop w=160 h=46   （一行四字）
"{测试}ABC"   -> crop w=114 h=46   （只剩 ABC）
"AB\NCD"      -> crop w=80  h=126  （\N 确实换行）
"AB\\NCD"     -> crop w=100 h=126  （双反斜杠并不能安全转义，仍被拆行）
"AB\ NCD"     -> crop w=252 h=54   （反斜杠被吞，空格保留）

# fontsdir 实测（把一个未安装的测试字体改名为 FFFVedioProbeFont）
不带 fontsdir:
  fontselect: (FFFVedioProbeFont, 400, 0) -> ArialMT, 0, ArialMT
  Glyph 0x5B57 not found, selecting one more font for (FFFVedioProbeFont, 400, 0)
  fontselect: (FFFVedioProbeFont, 400, 0) -> MicrosoftYaHeiUI, 1, MicrosoftYaHeiUI
带 fontsdir='C\:/Users/.../fonts':
  fontselect: (FFFVedioProbeFont, 400, 0) -> FFFVedioProbeFont, 0, FFFVedioProbeFont

# 字重实测（同一句、80px、白像素数量 / 包围盒）
NotoSansSC-VF 默认实例（wght=100 Thin）: 4930 / 396x51
VF 实例化到 wght=400（静态 Regular）: 6671 / 401x52
静态 Regular + Bold=1（libass 合成粗体）: 8020 / 403x53
```

结论：VF 默认实例是 Thin，不适合直接作为默认字幕字体；内置静态 Regular 更稳。Bold 可以由 libass 合成，0.1.2 不必额外打包 Bold。

结论：

- **不能靠 `\\` 转义反斜杠**；应在写入 ASS 前把用户文本里的 `\`、`{`、`}` 映射成全角等价字符（`＼`、`｛`、`｝`），或直接拒绝并提示。推荐映射，保留可读性。
- Windows 版 ffmpeg 虽然使用 `directwrite` 字体提供器，`ass` 滤镜的 `fontsdir` 仍然生效；绝对路径按 `escapeFilterPath` 的方式转义（`C\:/...`）即可。内置字体因此可以脱离系统安装工作。

## 四、目标设计：剪辑与字幕一体化

### 4.1 阶段与交互（新增 BUILD_EDIT / CONFIRM_EDIT）

```text
RENDER_VIDEO
  └─ BUILD_EDIT（自动阶段；UI：剪辑预处理）
       ├─ 用成功 Renders 生成默认 VideoEditPlan：每个片段一个 clip，order=渲染顺序，enabled=true，in=0，out=实测时长
       ├─ 按 EditPlan 选段/裁剪/拼接/归一 → Run.Compose（预览画布）
       └─ 自动铺字幕：实测片段时长 + 声学对齐 + 断句 → cues（带 segmentId / offsetS）
  └─ CONFIRM_EDIT（人工关卡；UI：剪辑与字幕）
       ├─ 视频预览：<video src=run.compose.canvasUrl> + 前端字幕 DOM 叠加层
       ├─ 片段：启用/禁用、入点/出点；last_frame 下禁止排序，其他续接模式可排序
       ├─ 字幕：拖拽/微调起止、改文本/位置/字号、增删、实时校验
       ├─ 保存草稿（不确认）
       ├─ 应用剪辑（异步重建预览 + 重铺字幕，完成后回到本页）
       └─ 确认并合成 → COMPOSE
```

阶段映射（读取旧任务时转换，DB 不做批量迁移）：

| 旧阶段 | 新阶段 |
| --- | --- |
| `BUILD_SUBS` | `BUILD_EDIT` |
| `CONFIRM_SUBS` | `CONFIRM_EDIT` |
| `gate_subs` | `gate_edit` |

- Go 常量：`VideoStageBuildSubs` / `VideoStageConfirmSubs` 改为 `VideoStageBuildEdit` / `VideoStageConfirmEdit`，`VideoGateSubs` 改为 `VideoGateEdit`；流水线 `switch`、`ApproveVideoGate`、`RegenerateVideoStage` 的 case 同步替换。
- `normalizeVideoStage` 负责阶段映射；`ensureVideoGates` 把旧 `gate_subs` 的状态复制到 `gate_edit`，读旧键、写新键，避免旧任务在关卡页丢状态。
- **默认剪辑计划**：`BUILD_EDIT` 从 `Run.Renders` 中状态成功且文件仍存在的片段生成；没有 `Run.Edit` 的旧任务在进入该阶段时现生成，然后继续。
- **自动字幕**：新任务 `Subtitles` 默认 `true`；`BUILD_EDIT` 自动生成 `Run.Subtitles`，不需要用户再点「生成字幕」。旧任务 `subtitles=false` 仍不生成，但 `CONFIRM_EDIT` 仍会打开，顶部提供「为本次开启字幕并生成」。
- **视频预览**：预览画布是未烧字幕的拼接视频；字幕由前端 DOM 覆盖层按当前 cue 实时渲染，拖动时间轴或字幕条即可看到位置/字号/换行效果。最终成片仍由 ffmpeg 烧录。可选「生成 10 秒烧录预览」按钮不进 MVP。
- **异步应用剪辑**：`ApplyVideoEdit` 启动后台任务：任务进入 `BUILD_EDIT/running`，按当前 `Run.Edit` 重建 `Run.Compose` 并重映射字幕；成功后回 `CONFIRM_EDIT/waiting`，失败也回 `CONFIRM_EDIT/waiting` 并把错误写进 `Run.Warnings` / `Run.Logs`。应用期间前端禁止编辑和确认。
- **排序限制**：`ContinuationMode == "last_frame"` 时后端拒绝改变 `Order`（返回「尾帧延续模式下不支持调整片段顺序」），前端隐藏排序手柄和上移/下移按钮，只保留启用/禁用与入点/出点。禁用中间片段同样会打断尾帧链，保存时给 warning 但不阻止。
- **确认合成**：`CONFIRM_EDIT` 的 `ApproveVideoGate` 置 `Subtitles.Confirmed=true`，进入 `COMPOSE`；若 `Edit.Revision != Compose.EditRevision`，`COMPOSE` 先按最新 Edit 重建画布并重铺字幕，再烧录。
- `video_pipeline.go:1049` 旧的 `Subtitles == nil` 跳过逻辑删除：`RENDER_VIDEO` 成功后一律进入 `BUILD_EDIT`，没有成功片段才报错。

### 4.2 数据模型（只增字段，JSON 向后兼容）

```go
// video_models.go
type VideoEditClip struct {
    SegmentID       string  `json:"segmentId"`
    ShotID          string  `json:"shotId,omitempty"`
    Order           int     `json:"order"`           // 0-based，越小越靠前
    Enabled         bool    `json:"enabled"`
    InPoint         float64 `json:"inPoint"`         // 相对源片段起点，秒
    OutPoint        float64 `json:"outPoint"`        // 相对源片段起点，秒；0 表示到片尾
    SourceDurationS float64 `json:"sourceDurationS"` // 只读：probe 出来的源时长
}

type VideoEditPlan struct {
    Clips     []VideoEditClip `json:"clips"`
    Revision  int             `json:"revision"`  // 剪辑版本：顺序/启停/入出点变化时 +1，用于画布缓存失效
    UpdatedAt string          `json:"updatedAt"`
}

type VideoSubtitleIssue struct {
    Index   int    `json:"index"`
    Level   string `json:"level"` // error|warning
    Code    string `json:"code"`
    Message string `json:"message"`
}

// VideoRunContext 新增
Edit           *VideoEditPlan      `json:"edit,omitempty"`
SubtitleIssues []VideoSubtitleIssue `json:"subtitleIssues,omitempty"`

// VideoSubtitleCue 新增（均 omitempty，旧数据不受影响）
SegmentID string  `json:"segmentId,omitempty"` // 自动生成的 cue 归属片段
OffsetS   float64 `json:"offsetS,omitempty"`   // 相对片段起点的偏移，用于剪辑后重映射

// VideoComposePrep 新增
EditRevision int     `json:"editRevision"` // 与 Edit.Revision 对齐；不等就重建
DurationS    float64 `json:"durationS"`    // 画布实测总时长，前端时间轴上限
```

设计要点：

- `Order` 与 `Enabled` 决定拼接顺序与是否入片；`InPoint/OutPoint` 决定每段裁剪区间。新建默认 `enabled=true`；前端提交时始终显式发送布尔值。
- `last_frame` 续接模式下 `Order` 必须与当前顺序一致；后端比较提交顺序，发现变化直接拒绝，不静默忽略。
- `OutPoint <= InPoint` 视为非法，保存时拒绝并提示；`OutPoint == 0` 归一成 `SourceDurationS`。
- `Revision` 是**剪辑**缓存键：只在 `Clips` 的顺序/启停/入出点发生实质变化时 +1；只改字幕文本或时间不改 `Revision`，避免无谓重建视频。`composePrepUsable` 必须同时比较 `prep.EditRevision == run.Edit.Revision`，否则重排/裁剪后仍复用旧画布。
- `OffsetS` 让字幕在剪辑后按「段内相对位置」重映射，保留用户改过的文本与大致节奏；没有 `SegmentID` 的手工 cue 按绝对时间保留，越界时提示。
- `SubtitleIssues` 持久化上次保存/自动铺轴的校验结果，刷新后仍能看到问题；错误级不为空时禁止确认合成。

### 4.3 后端 API

| API | 作用 | 是否阻塞 |
| --- | --- | --- |
| `SaveVideoEdit(id, VideoEditEdit) (VideoTask, error)` | 保存剪辑计划 + 字幕草稿；跑校验；仅在片段顺序/启停/入出点变化时 `Revision+1`；**不置 Confirmed、不重建预览**；`last_frame` 下校验顺序未被修改 | 快，纯 DB + 校验 |
| `ValidateVideoEdit(id, VideoEditEdit) ([]VideoSubtitleIssue, error)` | 实时校验（前端也可本地镜像；后端为准） | 快 |
| `ApplyVideoEdit(id) error` | 异步应用当前 Edit：若 `Revision` 变化则重建 `Run.Compose` 画布并按新时间轴重铺/重映射字幕；若只看字幕草稿则直接返回；任务进 `BUILD_EDIT/running`，完成后回 `CONFIRM_EDIT/waiting` | 慢（ffmpeg）或秒级（无剪辑变化） |
| `RelayoutVideoSubtitles(id) error` | 按当前画布重新测时与声学对齐，**覆盖现有 cue**（手工修改会丢失，前端二次确认）；任务进 `BUILD_EDIT/running`，完成后回 `CONFIRM_EDIT/waiting` | 中/慢 |

| `SetVideoSubtitlesEnabled(id, bool) (VideoTask, error)` | **仅旧任务兼容**：旧任务 `subtitles=false` 时一键开启并自动铺轴；新任务不显示该开关 | 中 |

`ApproveVideoGate` 的语义调整：

- 在 `CONFIRM_EDIT` 只做「确认」：置 `Subtitles.Confirmed=true`，不再顺带保存编辑。
- 编辑保存与应用走 `SaveVideoEdit` / `ApplyVideoEdit`，避免「保存=确认」的歧义。
- 旧 `SaveVideoSubtitles` / `applySubtitleEdits` 保留给旧任务与旧前端（仍为保存即 `Confirmed=true`）；新任务不再调用，避免误确认。
- `SaveVideoEdit` 发现 `last_frame` 下 `Order` 变化、`OutPoint <= InPoint`、或存在 error 级字幕问题时直接返回错误，不写库。

异步应用剪辑的状态机：

```text
CONFIRM_EDIT/waiting
  └─ ApplyVideoEdit → BUILD_EDIT/running
       ├─ 成功：Run.Compose 更新（EditRevision/DurationS）→ CONFIRM_EDIT/waiting
       ├─ 失败：保留旧 Compose，写 Run.Warnings + Run.Logs → CONFIRM_EDIT/waiting
       └─ 期间：isVideoTaskRunning=true，SaveVideoEdit/ApproveVideoGate 均拒绝
```

`ApplyVideoEdit` 不烧字幕，只重建预览画布和字幕时间轴；真正烧录仍由 `COMPOSE` 完成。若 `Compose.EditRevision == Edit.Revision` 且 `composePrepUsable` 通过，则跳过画布重建，也**不重新铺轴**（保留用户字幕草稿），直接回到 `CONFIRM_EDIT`。前端可在 `BUILD_EDIT/running` 显示「正在重建预览」与日志尾部。

新增 `relayoutSubtitleCues(oldEdit, newEdit, oldCues, newSpans) ([]VideoSubtitleCue, []string)`：

> `last_frame` 下顺序不变，但仍会因裁剪/启停改变每段起点与时长，所以同样要走段内偏移重映射。

1. 建立 `oldSpansBySegment`（用旧 Edit + 实测时长）与 `newSpansBySegment`。
2. 对每条 cue：
   - 有 `SegmentID`：
     - 新 Edit 中该段被禁用 → 丢弃，记一条 warning「第 N 段已禁用，其字幕一并移除」。

4. 返回新 cue 列表 + 用户可见的变更说明，写入 `Run.Warnings` / `Run.Logs`。

- 用「当前 Edit + 当前 Compose 实测时长」把每条带 `SegmentID` 的 cue 的 `OffsetS` 重算一遍（`cue.Start - currentSpan.Start`），这样用户手工拖过的时间也能在下次重排时保留。

## 五、字幕修复与校验（需求 3 / 8 / 9）

### 5.1 文本安全（P0）

新增 `assEscapeText(text string) string`：

- `\` → `＼`（U+FF3C）
- `{` → `｛`（U+FF5B）
- `}` → `｝`（U+FF5D）
- 先按行拆分，再对每行转义，最后用 `\N` 连接；**不要先转义再替换换行**，否则 `\N` 会被二次处理。
- `renderSRT` 保持原文（SRT 不需要 ASS 转义），但要校验/替换 `-->`，避免破坏 SRT 结构。
- 回归测试：`{测试}ABC`、`C:\new\N`、`AB\NCD` 渲染后文本内容与预期一致（可用 cropdetect 宽度/高度做近似断言，或直接断言生成的 ASS 文本字段）。

### 5.2 断句与换行（P0）

- `splitDialogueSentences` 增加二级切分：
  1. 先按句末标点/换行切。
  2. 单句超过「每行上限 × 2」时，再按 `，、,;；` 和空格切；英文优先在空格处切。
  3. 仍超长时按字符硬切，但**绝不丢尾**。
- `wrapSubtitleText` 改为「返回所有行」：
  - 中文每行 ≤18 字，英文每行 ≤42 字符，最多 3 行。
  - 超过 3 行时，调用方先把该句拆成多条 cue（`appendEstimatedCues` 内做），而不是截断。

### 5.3 时间轴、重叠、越界、阅读速度（P0/P1）

统一规则（前后端共用口径）：

| 规则 | 级别 | 处理 |
| --- | --- | --- |
| 文本为空 | error | 保存时丢弃该条并提示 |
| 单条时长 < 0.4s | error | 自动向后延长到 0.4s；无法延长则报错 |
| 与相邻条重叠 | error | 保存时自动消解：前一条 end 收到后一条 start - 0.05；不足 0.4s 则后一条顺延 |
| 结束超过成片时长 | error | 夹到 total；start 已越界则丢弃并逐条提示，**不再统一贴片尾** |
| 阅读速度 > 8 字/秒（英文 8 词/秒） | warning | 提示「第 N 条语速过快，建议拆分或延长」 |
| 中文单行 > 18 字 / 英文单行 > 42 字符 | warning | 保存时自动换行，并提示 |
| 字体不可用 | warning | 提示并建议改用内置 Noto Sans SC |
| cue 数 > 200 | warning | 上限提高到 1000；超过 1000 才截断并明确告警 |

### 5.4 声学对齐增强（P1）

- `extractSpeechWav` 增加带通：`highpass=f=200,lowpass=f=3400`，降低 BGM/低频噪声干扰。

- 增加覆盖率上限：`speechCoverageMax = 0.95`；某段窗口几乎覆盖全段时判定「检测不可信」，退回估算，避免把整段静音当说话。

  - `FillWindow` 不再无条件拉满；只有 `TimingSource == aligned` 时才允许铺满说话窗口。
  - 对齐失败时按 `estimateSpeechSeconds` 铺轴，短句不挂满整段。
- `TimingSource` 与失败原因写入 `Run.Subtitles`/`Run.Warnings`，编辑页显示「对齐成功 / 按实测 / 按估算（原因）」。
- 可选增强（不进 MVP）：用 `ffmpeg` 的 `astats`/能量包络做简易 VAD，替代纯 `silencedetect`。

### 5.5 字体（P0/P1）

- 0.1.2 **内置 Noto Sans SC**，不再依赖用户机器安装「思源黑体」。实现细节见 4.4「字体目录」：
  - `assets/fonts/NotoSansSC-Regular.otf`（约 8.3 MB，SIL OFL 1.1）+ `OFL.txt`。
  - `//go:embed` 进二进制，运行时 `ensureSubtitleFontDir()` 解压到工作目录。
  - `ass=` 滤镜追加 `:fontsdir=<字体目录>`；已实测未安装字体也能被 libass 选中。
- `normalizeVideoConfig` 的默认 `SubtitleStyle.FontName` 改为 `Noto Sans SC`；前端 `createEmptyVideoConfig` 同步。
- `checkSubtitleFont(fontName)` 仅用于用户自定义字体：
  - Windows 检查 `C:\Windows\Fonts` 下已知字体文件名（msyh.ttc、simhei.ttf、simsun.ttc、NotoSansSC-Regular.otf、NotoSansSC-VF.ttf 等）。
  - macOS/Linux 用 `fc-match`（有则用，没有则跳过）。
  - 不可用时返回 warning，并在 UI 提示「当前字体可能不存在，建议改用 Noto Sans SC / 安装字体」。
- 内置字体提取失败时：写 warning，合成继续但不带 `fontsdir`，退回系统字体；不能因为字体问题阻断成片。
- 模板里的 `subtitleStyle.fontName` 仍可覆盖；覆盖为系统中不存在的字体时，libass 会回退，UI 给出 warning，但不阻止合成。

### 5.6 烧录失败可见化（P1）

- `finalizeVideo` 降级时，把失败原因写进 `VideoOutput.Note`，并设置 `BurnSubtitles=false`。
- 前端输出区用 error badge 显示「字幕未烧录：<原因>」，并提供「重新合成」按钮。
- 合成阶段若 `cfg.Subtitles && !output.BurnSubtitles`，在任务详情顶部显示醒目提示，而不是只放在日志里。

## 六、需求 10 缩水版：音色绑定视频生成提示词

现状：`CharacterLibrary` 已能编辑 `voiceHint` 与 `VoiceProfile{voiceId, rate, pitch, volume, emotion}`（`CharacterLibrary.vue:314-340`），`normalizeVideoVoiceProfile` 已做夹取（`video_models.go:821-844`）；但渲染层只用了 `voiceHint`（`video_agent.go:481-483`），`VoiceProfile` 完全没进提示词。

目标：**不接 TTS，只把音色作为提示词约束传给原生音频模型**。

1. `characterProfileLine`（`video_agent.go:456-485`）追加紧凑音色摘要：
   ```
   ｜声音：温暖中音（音色 warm-male；语速 1.1x；音高 +2；情绪 calm；音量 0.9）
   ```
   没有 `voiceHint` 时用 `VoiceProfile` 拼；两者都没有就不输出。
2. `dialoguePromptBlock`（`video_adapter.go:377-435`）在 `caps.NativeAudio` 时追加每个说话人的音色行：
   ```
   音色：host = 温暖中音（1.1x，calm，+2）；narration = 低沉男声（1.0x，calm）
   ```
   只在段内出现过的说话人输出，避免整张角色表重复。
3. `composeRenderPrompt` 不改结构；音色作为 `dialoguePromptBlock` 的一部分，保证「提示词关卡看到的 = 发给模型的」。
4. 非原生音频模型：音色只留在角色表里供 Agent2 理解人设，不写入画面提示词（避免模型把「声音」画成画面元素）。
5. 测试：
   - 原生音频 + `voiceHint` / `VoiceProfile` → 提示词包含音色摘要，且不重复。
   - 非原生音频 → 提示词不出现音色指令。
   - 多说话人 → 每个说话人一行，旁白也标注。

不做的部分：TTS 合成、音色克隆、外部 API Key、成本计费、音频轨替换。

## 十、风险与决策

### 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 每次「应用剪辑」都要重编码 | 等待时间长、磁盘占用 | 仅在 `Revision` 变化时重建；缓存 `ComposedBySegment`；UI 显示进度；超时保护。 |
| `last_frame` 下启停中间片段 | 上一段尾帧不再对应下一段首帧，画面跳变 | 允许但保存时强提示；排序直接禁止；用户确认后再应用。 |
| 字幕重映射语义复杂 | 用户手工改的时间在裁剪后偏移 | 采用段内 `OffsetS`；保存时重算；越界明确告警；提供「按新时间轴重铺」一键恢复。 |
| 声学对齐受 BGM/噪声影响 | 仍可能不同步 | 带通 + 噪声门 + 覆盖率上下限 + 失败原因可见；最差退回估算。 |
| DOM 预览与 ffmpeg 烧录不一致 | 预览字号/边距与成片有偏差 | 预览和 ASS 共用同一套百分比口径；验收时对比同一 cue；偏差大时以成片为准并记录。 |
| 内置字体体积 | 安装包 +9 MB；仓库变大 | 用静态 Regular 覆盖默认字重，Bold 由 libass 合成；构建时检查哈希；后续可做子集。 |
| 阶段迁移遗漏 | 旧任务卡在 `CONFIRM_SUBS` 或关卡状态丢失 | `normalizeVideoStage` + `ensureVideoGates` 双向兼容；加迁移单测；保留旧分支。 |
| `prepareComposeCanvas` 改动大 | 影响现有合成稳定性 | 保留旧分支（无 Edit 时走原逻辑）；新增集成测试；分阶段合入。 |
| 异步应用期间用户继续编辑 | 旧 Revision 覆盖新编辑 | 应用期间 `isVideoTaskRunning=true`，保存/确认/应用均拒绝；前端只读并轮询。 |
| Wails 绑定忘记更新 | 前端调用 undefined | 把 `wails generate`/build 写进发布清单；typecheck 兜底；`backend.ts` 手写接口同步。 |

### 已确认决策

1. **阶段**：新增 `BUILD_EDIT` / `CONFIRM_EDIT`；旧 `BUILD_SUBS` / `CONFIRM_SUBS` 读时映射，`gate_subs` → `gate_edit`。
2. **字幕开关**：新建任务移除「生成字幕」开关，新任务默认生成；旧任务 `subtitles=false` 保持不变，剪辑页提供一键开启。
3. **自动时间轴**：`BUILD_EDIT` 生成后自动按实测片段 + 声学对齐铺字幕；`CONFIRM_EDIT` 支持拖拽和 ±0.1s 微调。
4. **尾帧延续**：`last_frame` 下禁止排序，只允许裁剪/启停；`none`/`overlap` 可排序。
5. **字体**：内置 Noto Sans SC Regular（`assets/fonts/NotoSansSC-Regular.otf` + OFL），运行时解压并通过 `ass` 的 `fontsdir` 指定；Bold 由 libass 合成。
6. **预览**：`CONFIRM_EDIT` 用 `run.compose.canvasUrl` + DOM 字幕覆盖层预览；最终成片由 ffmpeg 烧录。
7. **应用剪辑**：异步后台重建，任务进 `BUILD_EDIT/running`，完成后回 `CONFIRM_EDIT/waiting`。
8. **字幕重映射**：默认按段内 `OffsetS` 重映射并保留文本；越界逐条告警；另提供「按新时间轴重铺」。
9. **cue 上限**：200 → 1000，超过 1000 才截断并明确告警。
10. **音色范围**：只对 `caps.NativeAudio` 的模型写入音色提示词，非原生模型不写；不接 TTS、不产生额外费用。
