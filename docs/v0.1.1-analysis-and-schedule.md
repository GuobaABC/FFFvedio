# v0.1.1 需求源码分析与排期

> 版本基线：v0.1.0（本地 `main` = `5107740`，标签 `v0.1.0` 已存在）
> 分析方式：基于本地源码；需求 1、2、4、5、6、11、12 已实施，其余仍为分析/排期
> 分析范围：12 项 bug / 功能需求
> 文档日期：2026-11-08
> 实施状态：1、2、4、5、6、11 已改代码并通过 Go 测试与前端构建，未提交、未推送；9 按用户要求暂不动；12 只完成调研，未改代码

---

## 一、结论速览

- 12 项需求总量约 **31–37 人日**。
- 1 名全职开发约 **6–8 周**；2 名开发并行约 **4–4.5 周**。
- 建议拆成两个版本：
  - **v0.1.1（2 周）**：主流程修复 —— 需求 1、2、4、6、9、11、12
  - **v0.1.2（2 周）**：字幕与角色能力 —— 需求 3、5、7、8、10
- 若要求 12 项全部进 v0.1.1，整体顺延到 **12/08 左右**，并把需求 7 限制在 MVP 范围。

### 优先级

| 优先级 | 需求 | 理由 |
| --- | --- | --- |
| P0 | 1、2、4、9、11、12 | 直接影响「改了没生效」、成片质量、台词归属与烧额度前的控制 |
| P1 | 3、5、6、8 | 字幕可读性、角色复用、提示词一致性 |
| P2 | 7、10 | 新能力，工作量与外部依赖最大 |

### 关键依赖

- `1 ↔ 11`：段落时长编辑和段落提示词确认共用同一套段落数据。
- `4 ↔ 11`：提示词编辑要成为唯一权威源，段落确认才有意义。
- `5 ↔ 10`：角色档案同时承载外观和声音配置。
- `5 ↔ 12`：角色库的 role_id 是台词归属的唯一锚点，必须唯一且可追踪。
- `11 ↔ 12`：生成前确认与逐段返工都应能改台词归属，且不能只改台词不改归属。
- `10 ↔ 12`：TTS 要按角色音色出声，台词归属必须先准确落到角色。
- `3 ↔ 8 ↔ 9`：字幕规范化、校验、手工编辑必须共用同一套规则。
- `7 ↔ 3/9`：重新剪辑会改变时间轴，字幕必须重铺或重新确认。

## 二、逐项源码分析

### P0：直接影响主流程或成片

#### 需求 1：用户修改视频时间段无效

**现象**

用户修改时长后，成片长度或内容看起来没有按预期变化。

**源码定位**

当前有三处会让「改了时长」看起来没生效：

1. **提示词关卡没有时长字段**
   - `VideoPromptEdit` 只有 `shotId / visualPrompt / dialogue / speaker`（`video_models.go` 约 395 行）。
   - `applyPromptEdits` 也只改提示词和台词（`video_pipeline.go:566-594`）。
   - 结论：在关卡②没有修改时长的入口。

2. **模型档位取整导致时长漂移**
   - `buildVideoPlan` 用 `item.End - item.Start` 作为时长（`video_models.go:851-857`）。
   - 再经过 `splitShotDurations` + `nearestAllowedDuration`（`video_models.go:770-821`）。
   - 例：12 秒在 `[5,10]` 档位下 → 2×6 → 各取 5 → 实际 10 秒；18 秒 → 2×9 → 各取 10 → 实际 20 秒。
   - 现有测试 `video_test.go:94-115` 就是在断言 `18s → 20s`，说明当前行为是被测试固化下来的。

3. **长镜头切分只保留首段台词**
   - 一个镜头拆成多段时，只有第一段带台词（`video_models.go:868-873`）。
   - 后续段没有台词预算，用户会感觉「段时长变了但内容没变」。

**建议方案**

- 把 `durationS` 加入 `VideoPromptEdit` / `VideoSegmentRegen`，关卡②可直接改每段时长并重算计划。
- 修改 `splitShotDurations`：先按档位分配，再把余数补给最后一段，避免平均后取整造成整秒丢失。
- 计划里同时显示「请求时长 / 实际档位时长 / 差额」，确认前让用户看到真实成本与成片长度。
- 任务创建后如需允许改总时长，需新增配置更新接口；目前没有该入口。

**工作量**：2–3 人日

**验收标准（待确认）**

- 用户把总时长改为 18s，计划显示的实际时长与档位差额，且成片长度符合展示值。
- 修改单段时长后，重算计划、提示词预算、字幕时间轴全部同步。
- 长镜头切分后每段都有对应的台词/内容预算。

#### 需求 2：读字频率问题

**现象**

用户调整语速后，模型实际读字速度没有变化。

**源码定位**

当前语速只参与「预算和估算」，**没有真正控制模型读字速度**：

- 默认中文 4.0 字/秒（`video_models.go:499-503`）。
- 估算公式：`字数 / 语速 + 0.3`（`video_models.go:759-767`）。
- Agent1 给模型的台词上限是 `(段时长 - 0.3) × 语速`（`video_agent.go:157`）。
- 本地兜底裁台词用的是 `duration × rate`（`video_agent.go:949-971`），**少减了 0.3 秒**，与估算公式不一致，会出现「刚好卡预算却被判超时」。
- 渲染时 `composeRenderPrompt` 只把台词拼进提示词，没有传「语速 X 字/秒」（`video_adapter.go:362-378`）；原生音频模型按自己的节奏读，用户设置的语速不会生效。

**建议方案**

- 先统一预算公式为 `(duration - 0.3) × rate`，修掉本地裁台词不一致的问题。
- 原生音频通道在提示词里加「语速约 X 字/秒」的软约束。
- 增加「实测语速」回写：从声学对齐的说话窗口反算实际字/秒，按模型/音色积累校准值；后续接 TTS 后语速才真正可控。
- 明确产品预期：不接 TTS 时，语速只能影响台词长度和字幕估算，不能精确控制模型发音速度。

**工作量**：1.5–2 人日

**验收标准（待确认）**

- 预算、估算、裁台词三处公式完全一致。
- 原生音频提示词中包含语速约束。
- 日志或任务详情能看到「设置语速 / 实测语速」对比。

#### 需求 4：手工修改提示词阶段还没用

**现象**

在提示词关卡修改并保存后，感觉没有生效；或单段重生成时修改的提示词丢失。

**源码定位**

后端代码路径是存在的：关卡②保存 → `applyPromptEdits` → 重建 `Plan`（`video_pipeline.go:346-376`），前端也有「保存提示词修改」（`VideoTaskDetail.vue:316-321`）。但有几个结构性缺口：

1. 保存后只是 `gate2 = pending`，还要再点「确认提示词」才真正进入渲染；用户若以为保存即生效，会看到画面没变。
2. 单段重生成时只改 `Plan.Segments[target].Prompt`，**没有同步回 `Run.Prompts`**（`video_pipeline.go:245-248`）；后续计划重建或回到关卡②时，这段修改会丢失。
3. 点「按意见重新生成提示词」会用 Agent2 重写整批提示词，覆盖手工修改。
4. 保存时不做空提示词校验，也不提示哪些段被修改/被覆盖。
5. `applyPromptEdits` 未命中 `shotId` 时静默忽略（`video_pipeline.go:571-575`）。

**建议方案**

- 以 `Run.Prompts` 作为唯一权威源，单段编辑也要同步回写。
- 保存后明确显示「已保存，待确认」或直接允许「保存并确认」。
- 记录编辑版本/时间，重新生成前提示「会覆盖手工修改」。
- 未命中 `shotId` 时给出错误而不是静默忽略。
- 空提示词保存前拦截并定位到具体段。

**工作量**：1.5–2 人日

**验收标准（待确认）**

- 单段修改提示词后，`Run.Prompts` 与 `Plan.Segments` 保持一致。
- 保存后 UI 明确区分「已保存」与「已确认」。
- 重新生成前有覆盖提示，用户可取消。

#### 需求 9：手工修改字幕有问题

**现象**

手工改字幕时出现溢出、叠字、字幕消失或保存后行为不符合预期。

**源码定位**

- **手工文本不自动换行**：自动字幕走 `wrapSubtitleText`，但 `renderASS` 直接使用 `cue.Text`（`video_compose.go:1183-1200`），长句会溢出画面。
- **ASS 特殊字符未转义**：用户输入 `{}`、反斜杠会被当作 ASS 控制标签，可能出现字幕消失或样式被改写。
- **重叠字幕不处理**：`normalizeSubtitleCues` 只夹取起止、排序、重编号（`video_models.go:935-971`），不解决重叠，两条字幕会叠在一起。
- **越界字幕集中贴片尾**：起始时间超过成片时统一改成 `total - 0.4`（`video_models.go:952-956`），多条会堆在同一位置。
- **总时长兜底可能不准**：`applySubtitleEdits` 优先测画布，测不到就退回 `config.DurationS`（`video_pipeline.go:429-441`），与真实成片长度可能不一致。
- **保存即确认**：`applySubtitleEdits` 每次保存都设置 `Confirmed = true`（`video_pipeline.go:463`），用户可能以为只是暂存，实际上合成阶段已按它烧录。

**建议方案**

- 保存时统一做：换行、ASS 转义、重叠消解、越界裁剪，并把规范化后的结果返回前端。
- 区分「保存草稿」和「确认烧录」，或在 UI 明确提示。
- 增加逐条问题提示，和需求 8 共用校验规则。

**工作量**：2 人日

**验收标准（待确认）**

- 手工长文本自动换行，不溢出画面。
- `{}`、`\`、`\N` 等字符按普通文本显示，不破坏样式。
- 重叠字幕保存时自动消解或明确报错。
- 「保存」与「确认」语义分离。

#### 需求 11：生成下一段前应先确认提示词

**现象**

开启逐段确认后，下一段的提示词没有在烧额度前给用户确认。

**源码定位**

- `runRenderStage` 每段生成成功才设置 `ReviewPendingSegment` 并返回（`video_pipeline.go:1168-1175`）。
- `ApproveVideoSegment` 清空待确认标记后直接继续生成下一段（`video_pipeline.go:183-213`）。
- 也就是说下一段的提示词没有在烧额度前给用户确认。

**建议方案**

- 新增「段落提示词确认」状态，例如 `ReviewPendingPromptSegment` / `CONFIRM_SEGMENT_PROMPT`。
- 开启逐段确认时，第 N 段（N ≥ 2）生成前暂停，展示该段提示词、台词、时长、首帧来源，用户确认或修改后再提交。
- 新增接口：保存并生成本段、跳过本段确认、沿用上段设置。
- 注意断点续跑：已成功片段仍复用，不要重复暂停。
- 与需求 1、4 共用同一套段落编辑数据。

**工作量**：2.5–3 人日

**验收标准（待确认）**

- 开启逐段确认后，每段提交生成前都能看到并修改提示词。
- 修改后仅重算本段及受尾帧链影响的下游段。
- 断点续跑不会对已成功片段重复暂停。

#### 需求 12：台词与角色绑定优化

**现象**

- AI 自动分镜里，模型写出的 `speaker` 实际不生效：多角色同段台词被当成旁白，单角色段落的旁白又被当成角色台词。
- 角色标识有前缀关系时说话人串位（如 `char_1` / `char_12`）。
- 角色名含「解说 / 旁白」时，角色本人被当成旁白。
- 角色 `role_id` 可以重复；改名或删除角色后，手填分镜的 `roles` / `speaker` 不跟随。
- 视频生成阶段无法改台词归属；长镜头拆成多段后，第 2 段起填的台词不会进字幕。
- AI 单段重写不知道说话人是谁，可能把说话人从画面里写没。

**源码定位**

1. **Agent1 解析丢 `speaker`（根因）**
   - `llmScript` 的局部结构体没有 `speaker` 字段（`video_agent.go:224-238`），构造 `VideoShot` 时也没有赋值（`video_agent.go:252-261`）。
   - 系统提示词明确要求模型输出 `speaker`（`video_agent.go:174-176`、`:189`、`:206`），但解析层直接丢弃。
   - 随后 `bindSpeakers` 只能按出场角色猜（`video_agent.go:758-795`）：多角色 → 旁白；单角色 → 那个角色。
   - 实测：`roles=[host,guest]`、`speaker=host` → 最终 `speaker=narration`，并告警「有台词但没写说话人」。
   - 反向也成立：`roles=[host]`、`speaker=narration` → 最终 `speaker=host`，旁白被改判成角色台词。
2. **模糊匹配优先于全局精确匹配**
   - `matchSpeakerRole` 按角色表顺序调用 `roleMatches`（`video_agent.go:693-705`、`video_pipeline.go:1620-1642`），每个角色内部先精确再包含。
   - 因此前一个角色的「包含匹配」会抢走后一个角色的「精确匹配」。
   - 实测：角色 `char_1` / `char_12`，`speaker=char_12` → 绑定到 `char_1`，无告警。
3. **旁白别名抢真实角色**
   - `isNarrationSpeaker` 用 `contains` 匹配「旁白 / 画外音 / 解说」（`video_agent.go:676-690`）。
   - `normalizeSpeaker` 与 `bindSpeakers` 都先判旁白、再查角色表（`video_agent.go:716-724`、`:770`）。
   - 实测：角色「解说员」说台词 → 最终 `speaker=narration`，角色失去声音与口型。
4. **角色标识不唯一**
   - `normalizeVideoConfig` 不检查重复 `roleId`（`video_models.go:721-768`）；角色库保存也不校验（`character_store.go`）。
   - 前端 `addCharacter` 用 `length + 1` 生成 ID（`VideoTaskCreate.vue:627-628`）：删除中间一行后再新增，会与现有 `char_N` 重复。
   - 重复 ID 让 `matchSpeakerRole`、`characterImagesForSegment`、说话人下拉都出现「同名不同人」。
5. **改名 / 删角色不联动分镜**
   - `removeCharacter` 只删角色与图片，不动 `manualShots.roles` / `speaker`（`VideoTaskCreate.vue:657`）。
   - `roleId` 输入框可直接改（`VideoTaskCreate.vue:1140`），提交时只做空值兜底（`:816-831`），不修正引用。
   - 结果：台词归属静默降级为旁白，或绑定到不存在的角色。
6. **生成阶段不能改归属**
   - `VideoSegmentRegen` 只有 `visualPrompt / dialogue`（`video_models.go:384-389`；`frontend/src/types/video.ts:329-333`）。
   - `applySegmentEdit` 不更新 `Speaker / SpeakerName`（`video_pipeline.go:286-297`）；`syncSegmentEditToPrompt` 也不会重绑（`:421-466`）。
   - 生成前确认面板与生成后返工面板都没有说话人选择（`VideoTaskDetail.vue:1062-1105`、`:1121-1133`）。
   - 用户一旦发现口型对错人，只能退回提示词关卡重来，已生成片段全部失效。
7. **长镜头拆段后台词口径不一致**
   - `buildVideoPlan` 只在首段下发台词与归属（`video_models.go:1090-1095`）。
   - `applySegmentEdit` 却对任意段都写 `segment.Dialogue`（`video_pipeline.go:295`），而 `syncSegmentEditToPrompt` 只回写首段（`:444-455`）。
   - 第 2 段起在返工面板填台词：该段会带着台词去渲染，但字幕与提示词不更新，形成「有声音、无字幕」。
8. **AI 单段重写不带说话人**
   - `SuggestSegmentPrompt` 的用户提示词只带台词、不带 `speaker`（`video_agent.go:1433-1451`）；system prompt 也没有「让说话人留在画面」的约束（`:1378-1390`）。
   - 改写结果没有 `promptMentionsSpeaker` 校验；该校验只在初次生成时执行（`:1249-1252`）。
9. **Agent2 的 `speaker` 实际无效**
   - 输出契约要求原样返回（`video_agent.go:1099`），但 `generatePrompts` 只在分镜归属为空时才使用（`:1241-1244`），且不校验模型是否擅自改人。
10. **说话人提及检测大小写敏感**
    - `promptMentionsSpeaker` 用区分大小写的 `strings.Contains`（`video_agent.go:728-752`），英文角色名 `Host` / `host` 会误报「画面没提到说话人」。

**实施结果（v0.1.1）**

已按「一段允许多个说话人」落地，不再限制为单一 `speaker`：

后端：

- 新增 `VideoDialogueLine{speaker,text}` 与 `DialogueLines`；`VideoShot` / `VideoPromptItem` / `VideoSegment` / `VideoPromptEdit` / `VideoSegmentRegen` 全部携带多行台词。
- `Dialogue` / `Speaker` 保留为兼容字段：旧任务只有单值时会自动升级成一行；多说话人时 `Speaker` 留空、`SpeakerName` 用「甲、乙」这类可读标签。
- Agent1 输出契约改为 `dialogueLines`，同时兼容旧 `dialogue` / `speaker`；Agent2 原样回显 `dialogueLines`，但分镜仍是台词归属的权威源。
- 每行台词独立解析归属：全局精确角色 → 唯一模糊角色 → 旁白别名 → 本段唯一出场角色 → 旁白并告警。
- 角色名命中角色表时优先于旁白别名；`char_1 / char_12` 这类前缀关系由精确匹配先行保证。
- 角色开口但不在 `roles` 时自动补进本段出场角色，保证参考图与画面都能找到这张脸。
- 台词归属块 `【本段台词归属】` 对所有视频模型统一追加，不依赖 `NativeAudio`：
  - 单角色：只有该角色开口，其他角色嘴唇闭合，镜头给到其面部；
  - 多角色：按台词顺序轮流开口，轮到谁就拍到谁；
  - 纯旁白：显式写「画面内无人开口、不安排任何对口型」。
- 台词原文只在 `caps.NativeAudio` 时写入提示词；无原生音频的模型只写表演约束，避免把台词画成画面文字。
- `buildVideoPlan` 把多行台词与多人显示名带进镜头首段；`applySegmentEdit` / `applyPromptEdits` / `syncSegmentEditToPrompt` 支持多行台词并回写 `Run.Prompts`。
- 长镜头拆段后，非首段禁止改台词，后端明确报错，避免「有声音、无字幕」。
- `characterImagesForSegment` 收集所有说话人的定妆图；角色匹配改为精确匹配，避免前缀串图。
- `normalizeVideoConfig` 拒绝重复 `role_id`。
- `SuggestSegmentPrompt` 带上逐行说话人与台词；返回后若说话人不在画面，自动补一句「画面中必须出现说话人……」。
- `promptMentionsSpeaker` 改为大小写不敏感。

前端：

- 新建任务手动分段：台词改为逐行编辑器（说话人下拉 + 文本 + 增删），一段可加多行。
- 角色 `role_id` 自动生成改为扫描已有 `char_N` 最大值 + 1；重复标识即时提示并在提交前拦截。
- 角色改名时同步手动分段里的 `roles` / 台词归属；删除角色时清理对应出场勾选、台词行与兼容字段。
- 分镜关卡、提示词关卡、生成前确认面板、生成后返工面板全部换成多行台词编辑器，并显示多人归属标签。
- 长镜头的后续段在逐段面板中禁用台词增改，并给出原因。

**验收标准**

- Agent1 返回的 `dialogueLines` 在分镜、提示词、渲染计划三处逐行一致；单角色旁白不被改判。
- `char_1 / char_12`、「解说员」等用例绑定正确。
- 同一段两个角色轮流说话时，提示词按顺序写明谁先开口、谁后开口，旁白句显式写无人开口。
- 重复 `roleId` 在新建时被拦截；改名 / 删角色后引用被同步。
- 生成前确认与逐段返工能改多行台词与说话人并生效；非首段不会出现「有台词无字幕」。
- AI 重写后若说话人不在画面，提示词会被补齐。
- 旧任务（无 `dialogueLines`）可正常加载并自动升级。

**不纳入本次（建议 0.2）**

- 画外角色配音（说话人是角色但不在画面）：需要把「台词归属」与「是否出镜」拆成两个字段，并依赖 TTS。
- 台词级时间轴与逐句字幕编辑：留给 0.1.2 的剪辑与字幕能力。

### P1：提示词一致性、字幕体验与角色能力

#### 需求 6：首帧与提示词冲突时，优先提示词的新画面

**现象**

首帧与提示词描述冲突时，模型过度锁定首帧，画面不按提示词变化。

**源码定位**

当前约束偏「锁首帧」：

- `imageCastDirective` 要求「画面主体与外观必须与参考图或本段起始帧保持一致」（`video_agent.go:84-86`）。
- Agent1 规则要求第一段与首帧衔接（`video_agent.go:164`）。
- Agent2 system prompt 只要求原样写入主体约束（`video_agent.go:1001`），没有说明「首帧只是起点，提示词描述后续变化」。

**建议方案**

在 Agent2 系统提示词追加：

> 首帧是起始状态，不是最终画面。提示词描述的是首帧之后发生的变化；当首帧的环境、构图、动作与提示词冲突时，以提示词的新画面为准，在开头 0.5–1 秒内自然过渡到新场景，仅保持主体身份（脸型、毛色、服装）连续，不锁死首帧背景与机位。

同时给 `localVisualPrompt`、单段 AI 建议提示词也加同一句，保证关闭文本模型时不丢约束。

**工作量**：0.5 人日（含冲突场景测试）

**验收标准（待确认）**

- 首帧与提示词冲突时，成片在开头 1 秒内过渡到提示词描述的场景。
- 主体身份（脸型、毛色、服装）保持连续。
- 关闭文本模型时本地兜底同样遵守该规则。

#### 需求 8：字幕即时校验

**现象**

字幕编辑时没有实时错误提示，保存后才发现问题。

**源码定位**

当前校验只在保存时由后端做，而且只做夹取，不做可读性判断：

- `normalizeSubtitleCues` 检查空文本、最短 0.4 秒、越界、锚点/字号范围（`video_models.go:935-971`）。
- 没有检查：重叠、阅读速度、单行字数、换行、字体是否可用。
- 前端只有输入框的 `min/max`，没有实时错误提示（`VideoTaskDetail.vue:852-940`）。

**建议方案**

- 定义一套共享规则：
  - 单条时长 ≥ 0.4s
  - 阅读速度 ≤ 8 字/秒
  - 中文每行 ≤ 18 字
  - 英文每行 ≤ 42 字符
  - 禁止重叠
  - 结束不超过成片时长
- 后端提供 `ValidateVideoSubtitles`，前端编辑时实时调用或本地镜像同一规则。
- UI 显示「第 N 条：语速过快 / 与上一条重叠 / 超出片长」，保存按钮标出问题数量。
- 与需求 9 的规范化逻辑共用，避免前后端两套口径。

**工作量**：2 人日

**验收标准（待确认）**

- 编辑字幕时实时显示具体问题与定位。
- 前后端校验结果一致。
- 保存按钮显示问题数量，存在阻断级问题时禁止确认。

#### 需求 3：字幕问题（需要具体复现）

**说明**

这是 11 项中最笼统的一项，需要具体案例才能锁定修复范围。

**源码定位**

代码里已看到这些薄弱点：

- 字幕默认关闭（`video_models.go:124`，测试 `video_test.go:525-540`）；用户若以为默认会生成，会直接「没有字幕」。
- 声学对齐固定 `-35dB`、最短静音 0.2s（`video_compose.go:770-777`）；BGM、环境噪声、连续说话都可能影响切分。
- 覆盖率低于 20% 会退回按片段测时（`video_compose.go:774`），此时字幕可能与真实说话错位。
- 长镜头拆成多段时，台词只在第一段（`video_models.go:868-873`），后续段没有字幕窗口。
- 字体只写名字，不检查系统是否安装；缺字体时 libass 会回退。
- 手工文本的换行/转义/重叠问题见需求 9。

**建议方案**

先按「不同步 / 不显示 / 断句不对 / 字体不对 / 烧录失败」收集 2–3 个具体案例，再做字幕链路专项修复。

**工作量**：2–3 人日（取决于复现范围）

**验收标准（待确认）**

- 每个复现案例都有对应回归测试或验收样本。
- 字幕时间轴与成片说话区间偏差在可接受范围内。
- 缺字体时有明确告警或自动回退。

#### 需求 5：角色提示词绑定功能

**现象**

角色只有任务级参考图，无法跨任务复用角色设定。

**源码定位**

- `VideoCharacterRef` 只有 `RoleID / Name / Images / ImageSource / VoiceHint`（`video_models.go:77-85`），**没有外观锚点、性格、固定提示词**。
- 模板角色有 `AppearanceBlock`（`template_models.go:65-72`），但用户自己加的角色没有。
- `characterTable` 只在模板有外观时列出（`video_agent.go:336-345`）。
- `applyTemplatePromptExtras` 也只注入模板角色的外观（`video_agent.go:1230-1248`）。

**建议方案**

- 扩展角色模型：`appearanceBlock`、`persona`、`negativePrompt`、`voiceProfile`、默认参考图。
- 新增角色库（SQLite 表 + CRUD + 选择器），任务可引用角色库条目；模板角色也映射到同一结构。
- Agent1 / Agent2 / 本地兜底统一从角色档案生成外观锚点，避免多段画风漂移。
- 迁移旧 `characterRefs`，保持旧任务可复现。

**工作量**：3–4 人日

**验收标准（待确认）**

- 角色可保存到角色库并在新任务中复用。
- 同一角色在多段中的外观描述一致。
- 旧任务数据可正常加载。

### P2：新能力

#### 需求 10：角色声音定制

**现象**

目前只能写一行声音提示，无法真正定制角色音色。

**源码定位**

- `VoiceHint` 只是一行文字。
- `characterTable` 会输出「声音：低沉男声」（`video_agent.go:343-344`），但没有 TTS、没有音色 ID、没有音轨。
- 原生音频模型由模型自己决定声音；非原生音频模型根本没有配音，只有字幕。
- 合成阶段只做 BGM/水印混音（`video_compose.go:1265+`），没有角色对白音轨。

**建议方案（分两步）**

- **短期（0.5–1 人日）**
  - 把 `VoiceHint` 结构化，传给 Agent2 并在提示词中描述音色、语速、情绪。
  - 仅对支持音频描述的模型有效。
- **完整方案（5–7 人日）**
  - 接 TTS 提供商（Edge-TTS / Azure / 火山 / OpenAI 任选）。
  - 每个角色配置 `voiceId / rate / pitch / volume`。
  - 按台词生成音频，按段落对齐后与视频混音。
  - 字幕时间轴改用 TTS 实际时长，语速才真正可控。

**需要产品确认**

- 是否接受外部 TTS 成本与密钥配置。
- 是否要求离线可用。

**依赖**：需求 2（语速）、需求 5（角色档案）、需求 3/9（字幕时间轴）

**验收标准（待确认）**

- 每个角色可配置独立音色与语速。
- 对白音轨与画面段落对齐。
- 字幕时间轴基于实际音频时长。
- 未配置 TTS 时降级为提示词描述，不阻断出片。

#### 需求 7：手工剪辑成品视频

**现象**

目前只有自动预处理，用户无法对成片做手工剪辑。

**源码定位**

- `VideoComposePrep` 记录选段、冻帧裁剪、拼接、画幅归一（`video_models.go:306-319`）。
- `trimFrozenClipHeads`、`concatVideoClips` 都是自动逻辑（`video_compose.go:174+`、`406+`）。
- 前端没有时间轴编辑器，也没有「重剪/重合成」接口。

**建议方案（MVP，5–6 人日）**

**完整版**（多轨、分割、转场、撤销重做）建议放到 0.2.x。

**工作量**：MVP 5–6 人日

**验收标准（待确认）**

- 可调整片段顺序、启用/禁用、入点/出点并重新合成。
- 重新合成后字幕时间轴同步或明确提示需重新确认。
- 剪辑结果可持久化，刷新后不丢失。

## 六、需求 1 / 2 / 4 / 5 / 6 / 11 / 12 实施记录

### 需求 1：改时长真正生效

- `VideoPromptEdit` 新增 `durationS`，关卡②可直接改每段时长。
- `applyPromptEdits` 保存后重排整条时间轴，后续镜头整体顺延，并同步回 `Run.Script` / `ManualShots`，重算提示词时不会丢。
- `splitShotDurations` 改为「段数 × 档位」组合搜索：21s 在 `[5,10]` 下得到 `10+5+5=20s`，不再平均取整后只剩 15s。
- 计划卡片显示「目标 / 预计时长 / 档位差额」，单段显示当前计划时长。

### 需求 2：语速口径统一

- 新增 `speechPauseBufferS = 0.3` 与 `speechUnitBudget`，裁剪台词与估算公式统一为 `(时长 - 0.3) × 语速`。
- 原生音频模型渲染提示词追加「语速约 X 字/秒」软约束。
- 声学对齐后日志输出「设置语速 / 实测语速」对比。

### 需求 4：提示词修改生效且可追踪

- `Run.Prompts` 保持唯一权威源：单段重渲的提示词/台词会回写，重算计划不再丢。
- 未知 `shotId`、空提示词直接报错，不再静默忽略。
- 保存后 UI 明确提示「已保存，仍需点确认」；整批重新生成前提示会覆盖手工修改。

### 需求 6：首帧只作起始状态

- 新增 `firstFrameSemanticsDirective` / `firstFrameSemanticsBlock`：首帧是起始状态，不是最终画面；冲突时以提示词的新画面为准，开头 0.5–1 秒自然过渡，只保持主体身份连续。
